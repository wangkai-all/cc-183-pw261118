# 订单级费用分摊工作台（本地应用）

把订单级费用（运费、保价、优惠冲减等）按可切换规则分摊到商品行的本地数据加工页面。
**纯前端、零依赖、零构建**：无需联网、无需 npm install，双击 `index.html` 即可运行
（也可用 `npm run serve` 起本地静态服务）。所有数据保存在浏览器 `localStorage`。

## 运行方式

```bash
# 方式一：直接打开
open index.html          # 或文件管理器双击

# 方式二：本地静态服务
npm run serve            # 等价于 python3 -m http.server 8765
# 浏览器访问 http://127.0.0.1:8765/

# 测试（仅需 Node >= 18，零依赖）
npm test                 # 23 项引擎/不变量测试
npm run smoke            # DOM 冒烟测试（最小 DOM 桩，覆盖 UI 初始化与交互链路）
```

## 需求对照

| 需求 | 实现 |
| --- | --- |
| 按金额、重量、自定义权重分摊 | 三种规则可逐费用切换，也可一键全局切换（`js/engine.js` `BASIS`） |
| 来源费用、规则、商品版本固定在同一次计算 | 每次运行保存不可变快照 `sourceSnapshot`，运行记录与源版本双向绑定 |
| 退款/补录形成新版本，保留旧结果 | 修订即派生新版本（版本链 SV1→SV2→SV3…），旧版本冻结、旧运行永久保留 |
| 最小货币单位分配 | 金额全程整数「分」；权重按 1e6 定点整数化，无浮点参与金额运算 |
| 尾差稳定排序 | 最大余数法（largest remainder），余数相同时按显式输入行序裁决，逐行记录裁决序号 |
| 零权重、负费用、缺失商品策略 | 三类边界均有显式策略，见下文「边界策略」，任何金额都不允许凭空丢弃 |
| 每行分摊依据、未分配原因、订单级守恒核对 | 明细含理论份额/保底/尾差调整/裁决序；页面与 CSV 均输出守恒核对 |
| 切换规则、修订源数据、比较版本、下载明细 | 四个标签页对应全部操作；CSV（UTF-8 BOM，Excel 可开）与完整 JSON 双格式下载 |
| 失败时不发布部分结果 | 引擎聚合全部校验错误抛 `AllocationError`；存储层只登记 `failed` 记录，`result=null` |
| 同一输入与规则得到相同结果 | 纯函数引擎 + 规范化输入签名（FNV-1a 哈希）；重复提交幂等复用既有运行 |

## 分摊算法（`js/engine.js`）

对每条费用独立分摊，再做行级汇总与订单级核对：

1. **资格判定**：按所选规则取每行依据值（金额=整数分；重量/自定义权重=1e6 定点整数）。
   零依据行按 `zeroWeight` 策略处理。
2. **精确份额**：对费用绝对值 `A`、行权重 `wᵢ`、总权重 `W`，
   理论份额 = `A·wᵢ/W`，以整数乘除保留完整精度，保底取 `floor(A·wᵢ/W)`。
3. **尾差裁决**：剩余 `A − Σ保底` 个最小货币单位，按余数从大到小补发，
   余数相同按**输入行序**（稳定排序，不依赖任何运行时环境的排序特性）。
4. **符号还原**：负费用对全部结果取负，尾差标记同步显示 `-1 分`。
5. **守恒核对**：每条费用核对 `费用额 = 已分配 + 未分配`，订单级再汇总核对，差额必须为 0。

### 边界策略（随源版本快照固定）

| 策略键 | 取值 | 行为 |
| --- | --- | --- |
| `zeroWeight` | `exclude`（默认） | 零权重行不参与，费用由其余行全额分摊，行内注明排除原因 |
| | `error` | 任一参与行为零权重即整体失败，不发布结果 |
| | `equalShare` | 全部为零时按行数等权均分（仍走最大余数法处理尾差） |
| `negativeFee` | `allow`（默认） | 允许负费用，按同构规则分摊负金额（如优惠冲减） |
| | `error` | 出现负费用即整体失败 |
| `missingProduct` | `error`（默认） | 商品行引用的商品不在商品版本中 → 硬失败 |
| | `unallocated` | 缺失行不参与；其对应金额保留为「未分配」并注明原因，守恒仍成立 |

零权重导致**全部行**无分摊对象时，费用全额挂未分配并附原因——系统不存在“钱不知道去哪了”的状态。

## 版本与运行模型（`js/store.js`）

- **源版本 SourceVersion**：费用 + 商品行 + 商品主数据版本 + 默认规则 + 边界策略。落库即冻结。
- **修订**：深拷贝父版本 → 编辑 → 新版本号（SV4、SV5…），父版本不变。
- **运行 Run**：`版本 + 规则覆盖 + 策略` 经引擎计算的不可变结果；成功记录含完整明细与核对，
  失败记录含全部错误码且无结果字段。
- **幂等**：规范化快照哈希（`inputHash`）相同的重复提交直接复用既有运行，不产生新记录。
- **比较**：支持任意两个运行的逐行金额差异，以及任意两个源版本的费用/行/商品字段级 diff。

## 合成演示数据（`js/seed.js`）

固定订单 `O-20261110-0087`，预置三个源版本与多条运行（时间戳固定，任何环境首次加载一致）：

- **SV1 原始订单**：4 件商品、4 笔费用（含负费用）。预置混合规则运行、全重量规则运行、
  以及一次**同输入重复运行**（演示幂等复用）。
- **SV2 部分退款**：鼠标 L3 退货（金额/权重清零，状态 `refunded`），重新分摊，SV1 结果保留可对比。
- **SV3 补录商品**：新增 USB-C 扩展坞 L5，商品版本升 v3，重新分摊。
- **失败演示**：商品主数据缺失 P4 的草稿触发硬失败，展示错误聚合与“无部分结果发布”。

界面「源数据与版本」页提供修订向导，可一键模拟退款、补录、缺失商品并调整边界策略。

## 确定性说明

- 引擎不含 `Date`/`Math.random`；时间戳仅属于运行元数据，不参与 `inputHash`。
- 哈希前对对象做**键排序**的规范化 JSON；数组顺序属于输入快照的一部分（因此行序变化会改变签名，
  且尾差按各自输入序裁决——这正是“稳定排序”的语义）。
- 结果对象经 `deepFreeze` 冻结，防止界面或下游意外篡改已发布结果。
